# 青理竞赛通 2.4：社区、共享空间与学期成绩

## 安装与入口

安装交付目录中的「青理竞赛通-v2.4.0.apk」，可覆盖安装同签名旧版，无需卸载。支持 Android 8 及以上。首页保留竞赛通知、找队友、经验交流；工作台集中学业、综测、升学、简历、面试、资料和待办入口。

## 发帖与我的发布

找队友和经验交流现在使用相同的社区帖子布局：发布者说明、赛事、标题、正文摘要和查看帖子入口。招募帖另显示招募状态、现有人数和协作地点；点进去可以申请入队、处理申请和管理队内事项。经验帖可以看正文、收藏、评论和举报，评论与举报通过单独的编辑面板展开。

点击底部蓝色「＋」，选「找队友」或「发经验」。先写标题与正文，再点下面的标签选赛事、赛道、人数、时间安排等。赛事选择支持搜索 84 项目录，也能手动填写目录外赛事。招募需填赛事、标题、角色要求、赛道和安排；队伍人数为 2—30 人，包含队长。确认公开发布后，同一篇帖子会同时出现在对应社区及「我的 → 我的发布」。这里有全部、找队友、经验交流筛选，经验超过一页可加载更早发布。查看自己参与的队伍用社区的「我的队伍」，它与只展示本人发布内容的「我的发布」用途不同。

公开帖子不要填写成绩单、学号或私人联系方式。需要登录 App 邮箱账号才可以公开发布；仅写草稿不会发送到社区。团队申请或站内消息只有点击提交后才发送。

## 统一编辑方式与待办

招募、经验、资料说明、待办、申请事项和经历等使用同一套内容编辑器：标题在上，正文在中间，其他属性收进标签，点标签展开选择或补充。日期使用日期选择器，不需要手输日期格式。已有内容、草稿保存和提交校验保留。

「工作台 → 管理待办」点击添加，直接弹出底部面板。填写要做的事，按需补备注，点日期及来源标签后保存。新待办默认今天；事项列表直接显示标题、简短备注和日期，勾选完成，点卡片修改。待办是私人记录，不会变成社区帖子。云端备份仍由用户在账号页主动执行。

## 共享空间、我的网盘与打印

「资料库」集中三个页签：共享空间、我的网盘、资料打印。

共享空间默认按已加载文件的分类组成空间卡片，卡片预览文件名和文件数量。点卡片进入该分类，也可搜索名称、课程或赛事，按更新时间/名称排列，切换文件网格与列表。这是资料分类视图，目前没有新增群组成员或加入空间机制。页面的数量明确表示已加载内容，不冒充全站统计。

我的网盘保存私人文件。通过「＋ → 分享资料」选择文件，填写资料说明、分类，可选公开分享；私有文件只有自己可访问。文件菜单保留阅读、下载、取消公开、删除或举报。单文件不超过 10 MB，个人空间 200 MB。共享资料遵守原作者授权。

资料打印参考蓝色服务页的集中布局：选择手机文件，点「打印要求」设置黑白/彩色、单面/双面、装订、份数和页码。支持多文件排序和移除，最多 20 个文件，单文件 10 MB、合计 50 MB；份数 1—100，页码可填「全部」或「1-3,5」。导出得到原文件和文字打印清单 ZIP，已导出记录保存到本机。微信/QQ 文件先保存到手机，再选择；网盘通过系统文件选择器或先下载后选取。当前没有接入商家、价格、支付和配送，导出记录不代表下单成功。

## 教务成绩与 DeepSeek 逐科分析

先在综测系统使用本人学生身份登录教务，然后返回「成绩分析」，点「一键同步成绩并计算 GPA」。页面复用当前登录，不再重复要求填写教务密码。原有综测学生登录条件仍保留，包括班级名册匹配；本次没有放宽登录条件或改动综测规则。

读取成功后显示全部学期、各学期课程成绩与绩点，以及累计 GPA 和加权平均分。绩点直接采用教务原表数值，按课程学分加权；累计 GPA 不是各学期 GPA 的简单平均。等级成绩可以使用教务提供的绩点，但不会猜测百分制成绩。缺失绩点显示覆盖学分，不按零分计算。补考、重修、免修和未发布课程暂排除，学校最终认定以官方规则为准。

同步完整校验后才替换本机成绩。失败保留旧记录，成功前留存撤销快照；「撤销上一次成绩同步」可以恢复。若同步后手动修改了课程，撤销会提示核对，防止覆盖新编辑。教务要求验证码、会话过期或页面结构变化时，请重新登录或使用「导入 / 试算」中的文件导入。

点「DeepSeek 分析本学期每门课」可生成逐门建议；点击某门课程也能单独分析。需登录 App 邮箱账号并确认发送课程名称、学期、成绩、学分、绩点。不会把教务密码、姓名、学号作为模型输入。模型只提供学习建议，GPA 由程序计算；建议会区分已知成绩与需要自测的问题。

任务在服务器分步骤运行，离开页面后可在「消息 → AI任务」查看，返回成绩页会恢复最近一次任务。成功结果保存到私人工作区，失败可从失败步骤重试。AI 需要网络和平台模型额度，单次分析最多 60 门；成绩本身在本机保存后可以离线看。

## 服务维护与回退

本版 API 和 Java 服务均为 2.4.0，分别使用 18086、18088；综测管理前端 18089 保持原版本。只增加本人教务成绩读取接口，原有综测计算、规则、材料审核等源文件保持不变。服务器沿用现有 `.env` 的数据库、SMTP、模型配置，签名沿用之前的独立备份。

升级前备份目录：`/opt/qut-competition-backups/before-2.4.0-20260915-091127`。其中有旧 Compose、私有环境配置、容器元数据和 SQLite 在线备份。部署记录在 `/opt/qut-competition-releases/2.4.0`。本次没有数据库结构变更，回退应用可将旧 Compose 恢复后只重建 `api` 与 `zhcp-api`；不要用旧数据库覆盖升级后新增的用户数据。

重新部署：先在 JDK 17 下构建 `zhcp` 的 Maven 工程，再用项目的 Dockerfile 构建两个 API 镜像；在现有 `/opt/qut-competition` 保留 `.env` 和数据卷，执行 `docker-compose -p qut-competition up -d --no-deps api zhcp-api`。先备份并校验 Compose，勿覆盖其他容器。包内的 Java JAR 是本次实际部署的同一构建产物。

常见问题：无法发布先检查邮箱登录和必填标签；资料为空可换关键词或上传自己的文件；手机通知与邮箱提醒继续沿用原配置。QQ 群采集继续停用，两条旧通知保持已删除。后台提醒可能受安卓省电影响，邮箱提醒由服务器执行。详细历史功能见 2.3 使用说明。
