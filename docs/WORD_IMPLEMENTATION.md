# Word 方案实施记录

依据：用户提供的《青理竞赛通功能方案口语化详细版.docx》，2026-09-11 读取的版本。
基线：GitHub 20260322z/qut-competition，保留 Android、FastAPI、Java 综测和 Vue 团支书端。

## 实施顺序

1. 五入口和本地学生工作台：资料、成绩导入预览/加权分析、成长档案、目标院校、申请、任务、面试练习、打印准备。
2. 服务端邮箱身份、独立订阅、截止提醒、持久化发送队列；关闭和解绑取消待发送任务。
3. 有年份和来源的竞赛目录；实名度不夸大的组队申请/确认流程；经验、评论、举报。
4. 私有文件与主动分享、DeepSeek 简历任务、云端个人记录。
5. 构建、接口回归、模拟器检查、交付说明。未验证的外部系统和需要商家/发信配置的能力单独标注。

## 边界

- 复用现有学校身份和综测，平台邮箱身份不等同于在校生认证。
- 不编造比赛名单、官方绩点规则、用户投稿、录取概率或商家订单。
- 无 SMTP / AI 配置时返回明确未配置状态，不伪造成功。
- 保留原包名和签名，数据库迁移不删除旧通知、收藏和提醒。
- 先在本机完成验证；用户授权部署后，先备份，再更新本项目容器并检查数据库保留情况。

## 外部联调与剩余细节

2026-09-11 已按用户授权接受并固定校验本次 SSH 指纹，部署 Python 与 Java 2.0.0 后端。公网接口、84 项目录、私有接口的未登录拦截及重启后数据保留检查通过。QQ SMTP 已配置且真实认证成功；没有声称真实邮件到达收件箱或教务账户端到端联调成功。真实学生账号仍需用户本人联调。

完整 Word 还有后续细节：学院正式规则数据与证据双向联动、文件版本/应用内预览、复杂 PDF 合并、帖子图片和版本、目录额外结构化元数据。这些不能以空按钮或虚构数据冒充完成。详见使用与部署说明中的当前边界。
