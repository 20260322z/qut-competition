# 青理竞赛通 2.3：统一通知与紧凑界面

本次升级把工具集中到工作台，把 84 项目录赛事的通知接进首页。综测计算、教务和学工连接、加分库及综测管理端保持原样。

## 安装与更新

安装交付目录中的 `青理竞赛通-v2.3.0.apk`。支持 Android 8.0 及以上，版本号 2.3.0、内部版本号 7，沿用之前的正式签名。直接覆盖安装可保留原有数据，请不要先卸载。系统询问安装来源时，允许当前文件管理器安装即可。

服务地址预置为 `http://38.207.179.218:18086`。在“我的 → 设置与连接”可修改地址、测试连接和查看同步状态。没有网络时仍可查看已缓存的通知；切换服务器后，账号和私人工作内容按服务地址隔离。

## 五个入口怎么用

### 首页：集中查看通知和交流内容

顶部只保留“竞赛通知、找队友、经验交流”三个内容频道。通知页搜索竞赛名称或关键词；点“84项赛事”打开赛事筛选，搜到赛事后点击即可返回对应通知，不再跳进一套重复的赛事页面。可以点星标关注赛事，再用“已关注”筛选。校内通知和赛事来源共用同一信息流，同一原文链接不会因关联多个赛事重复出现。

分类标签用于科技、创业、设计、外语等筛选。右上角筛选可结合来源、已读状态及日期缩小范围。点“按截止查看”优先看临近事项。点通知进入详情，查看正文、附件、原文链接，设置提醒、收藏或分享。找队友和经验交流集中展示帖子；发布入口统一在底部“＋”。

84 项指沿用项目现有的 2023 版目录，并不是声称 2026 年最新目录仍为 84 项。目录内的来源档案、关注状态和采集状态都保留；待核验来源会明确标识，历史来源停采。动态网页、访问限制或尚未适配的页面不能保证解析成功，已有数据会保留并重试。未取得正文的来源不会显示成“本次已成功同步”。具体采集覆盖见随包测试结果及线上来源状态。

官网没有明确发布时间时显示“发布时间待确认”；含多个报名日期，或仅写某日而未写明确时刻时，不推算手机提醒的精确截止时间。可在详情自行选择提醒日期，原文证据保留供核对。

### 工作台：每项工具保留一个主入口

工作台集中放八个入口：综测系统、成绩分析、升学规划、日程提醒、简历优化、模拟面试、资料库、成长档案。上方搜索可查工作内容，下方显示未完成草稿和今天的待办，减少来回翻找。

简历优化和模拟面试仍是两个独立工作区。简历保留材料整理、诊断、逐段修改、事实核对、版本与 Word/PDF 导出；面试保留准备、问题练习、连续追问和复盘。升学规划集中管理目标及申请事项，不重复摆放简历、面试、资料入口。综测入口位置变化，内部功能没有调整。

资料库分公开资料、私人文件、打印准备。上传资料统一从“＋ → 分享资料”进入。打印准备是文件准备功能，仍未对接真实商家下单、支付和物流。

### ＋：发布只在这里

底部中间的蓝色“＋”弹出发布面板，选择找队友、发经验或分享资料，也可继续草稿。内容发布成功后显示结果，避免继续点击重复提交。需要账号的操作仍会要求邮箱登录。

### 消息：查看处理结果

分为赛事提醒、组队互动、AI任务。赛事提醒可看已读/未读并标记已读；组队互动显示站内互动；AI任务查看处理进度、历史和失败状态。这里不再重复放置各工具的启动按钮。

### 我的：个人内容与设置

集中放收藏、浏览记录、我的发布、账号、邮箱提醒、服务连接及触感设置。个人统计来自实际记录。未登录不会显示虚构姓名、学校认证或成绩。

## 提醒与 QQ 通知清理

手机通知需授予系统通知权限，拒绝权限仍能浏览。后台更新和提醒遵循 Android 的后台任务机制；系统省电、强行停止 App 等情况可能延迟或阻止提醒。邮箱提醒由服务器执行，与 App 是否在前台无关，但仍依赖用户保存并验证邮箱、打开订阅以及平台发信服务正常。

此次删除了服务器原有的 2 条 QQ 群通知，并停用 QQ 入库和回调。新版首次升级会清理本地 QQ 通知、对应收藏状态及提醒；同步接口同时传递删除记录。只清理 QQ 来源，不删除学校通知、其他竞赛、用户帖子和综测内容。服务器保留删除前的私有数据库备份以便误删恢复，备份不会出现在信息流。

## 后端维护

后端仍是 FastAPI + SQLite，数据位于 API 容器的 `/data/notices.db`。原有 SMTP、模型和综测数据库配置继续沿用服务器 `.env`。部署时只更新 API 容器，不重建综测服务。发行包不包含运行密码、数据库或签名私钥；继续使用此前独立保存的签名备份即可。

学校通知每小时同步。赛事目录按批次检查，通常每 5 分钟轮询 8 个到期来源，失败保留旧数据；访问慢时整轮会延长。可以在服务器手动执行：

```sh
docker exec qut-competition-api python -m app.manage sync
docker exec qut-competition-api python -m app.manage contest-sync --full
docker exec qut-competition-api python -m app.manage backup --output /data/manual-backup.db
```

数据库备份使用 SQLite 在线备份，避免直接拷贝正在写入的数据库。更新前备份 `/opt/qut-competition/.env`、Compose 配置和数据库，并保持备份私有。当前实际部署记录和回退路径在交付目录“验证记录”中。

连接失败先检查手机网络，再到设置中测试连接；无法收邮件时检查垃圾邮件、邮箱验证和提醒开关；特定赛事没有通知时查看该赛事来源状态，可点击官网入口自行核对。这个 App 是个人信息聚合工具，赛事报名、获奖认定及综测规则以学校和主办方通知为准。
